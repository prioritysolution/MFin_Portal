# Login API

```
POST /api/auth/login
```

## Request body

| JSON key | Type | Required | Description |
|----------|------|----------|-------------|
| `login` | string | Yes | `User_Name` **or** `User_Code` |
| `password` | string | Yes | Plain password (checked against bcrypt `User_Pass`) |

### Example — login with User_Name

```json
{
  "login": "admin",
  "password": "Admin@123"
}
```

### Example — login with User_Code

```json
{
  "login": "ADMIN001",
  "password": "Admin@123"
}
```

---

## Success response `200`

```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "token": "base64-hmac-token",
    "token_type": "Bearer",
    "expires_in": 28800,
    "org_schema": "priomicro_basundhara",
    "user": {
      "user_id": 1,
      "org_id": 1,
      "branch_id": 1,
      "user_name": "admin",
      "short_name": "Admin",
      "user_code": "ADMIN001",
      "user_mob": "9999999999",
      "user_email": "admin@basundhara.local",
      "is_active": true,
      "login_status": "LogIn",
      "org_disp_nm": "Basundhara Microfinance",
      "legal_name": "Basundhara Microfinance Private Limited",
      "org_schema": "priomicro_basundhara",
      "branch_code": "HO0001",
      "branch_name": "Head Office",
      "is_head": true,
      "role_id": 1,
      "role_name": "Super Admin",
      "is_admin": true,
      "roles": [
        { "role_id": 1, "role_name": "Super Admin", "is_admin": true }
      ]
    }
  }
}
```

---

## Error responses

| HTTP | When |
|------|------|
| `401` | Invalid login / password, or inactive user / org / branch |
| `422` | Validation failed (`login` or `password` missing) |

```json
{
  "success": false,
  "message": "Invalid credentials",
  "errors": null,
  "data": null
}
```

## cURL

```bash
curl -X POST "http://116.193.129.229:8080/api/auth/login" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{"login":"admin","password":"Admin@123"}'
```



# Logout API

```
POST /api/auth/logout
```

### Headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer {token}` |
| `Accept` | `application/json` |

---

## Success response `200`

```json
{
  "success": true,
  "message": "Logout successful",
  "data": null
}
```

---

## Error responses

| HTTP | When |
|------|------|
| `401` | Missing, invalid, or expired Bearer token / user not LogIn |
| `400` | Status update failed / user not found |

```json
{
  "success": false,
  "message": "Unauthorized. Bearer token required.",
  "errors": null,
  "data": null
}
```

---

## cURL

```bash
curl -X POST "http://116.193.129.229:8080/api/auth/logout" \
  -H "Authorization: Bearer YOUR_TOKEN_HERE" \
  -H "Accept: application/json"
```



# MenuTree API

## Request

```
GET /api/MenuTree
```

| Query | Type | Required | Description |
|-------|------|----------|-------------|
| `status` | int | No | Default `1` (active) |
| `role_id` | int | No | Restrict to one of the user's roles |

```bash
curl -X GET "http://116.193.129.229:8080/api/MenuTree" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Accept: application/json"
```

### Success `200`

```json
{
  "success": true,
  "message": "Menu tree retrieved successfully",
  "data": [
    {
      "menu_sl": 1,
      "menu_id": 1,
      "menu_name": "Dashboard",
      "icon": "LayoutDashboard",
      "route": "/dashboard",
      "status": 1,
      "children": []
    },
    {
      "menu_sl": 7,
      "menu_id": 2,
      "menu_name": "Master Menu",
      "icon": "Menu",
      "route": null,
      "status": 1,
      "children": [
        {
          "menu_sl": 8,
          "menu_id": 2,
          "submenu_id": 1,
          "submenu_name": "Organisation Profile",
          "icon": "Building2",
          "route": "/master/company-profile",
          "status": 1
        }
      ]
    }
  ]
}
```

Use this for sidebar navigation. Leaf nodes may have a `route` and empty `children`. Child `icon` / `route` may be `null`.

BFF: `GET /api/menu?status=1` — server sends `role_id` from the login session (`user.role_id`). Optional `?role_id=` is accepted only if that role is assigned to the signed-in user.

---

## Errors

| HTTP | When |
|------|------|
| `401` | Missing / invalid / expired token |
| `403` | Requested `role_id` not assigned to user |
| `500` | Unexpected DB error |

# WorkingHours API

| Item | Value |
|------|-------|
| Auth | `Authorization: Bearer {token}` |
| Database | `priomicro_basundhara` (tenant) |
| Table | `mst_timmings` |

### `mst_timmings` columns

`Id`, `SOD_Time`, `EOD_Time`, `BatchExe_Time`, `SessionInc_Time`

| Column | Meaning |
|--------|---------|
| `SOD_Time` | Start of day (opening) |
| `EOD_Time` | End of day (closing) |
| `BatchExe_Time` | Batch execution time |
| `SessionInc_Time` | Session inactivity timeout (as `HH:mm`) |

**Always update mode** — single institutional config row (upsert on save).

Times use **24-hour** `HH:mm` (e.g. `08:00`, `19:30`).
